# 放置武林(/games/wulin)— 基于 Vue 3 + PixiJS 重构《放置江湖》式武侠放置游戏

## 背景与调研结论

《放置江湖》:文字武侠放置 RPG(iOS/Android,约 2017 年上线,持续更新),MUD 血统。已从其官方 BWIKI(wiki.biligame.com/fzjh)检索到完整机制资料:

- **角色创建**:4 种出身(孤儿/武学世家/书香门第/商贾之家);先天属性 臂力+身法+根骨+悟性=80,容貌+福缘=40(福缘≤27,影响挂机收益);后天属性=基本武学每 10 级 +1,有效值=先天+后天/2
- **门派**:28 门派分正派/邪派/中立/隐藏四类,有属性/性别入门要求;可不入派玩「散人」
- **战斗**:自动实时制,三条槽——气血(HP,受伤降上限)/内力(MP,打坐可蓄至 2 倍上限)/行动条(满值 3.0,招式前后摇决定一条黄条出手次数);PVE 一条黄条连击(100%/60%/40% 递减伤害);随机招式+随机部位命中(头颈高伤、手足低伤);命中 vs 闪避、招架减伤;加力(内力附伤,上限=(基本内功/2+准备内功)/2);主动技能耗内力+CD(PVE 中 CD 随其他行动流逝)
- **面板公式**(公开):攻击力=(技能等级×0.03×攻击系数+内力上限/20+10+总经验^0.4)×(1+0.02×有效臂力);命中/闪避/防御/内力上限等同类公式,全部系数挂在武学数据上(转化率 37~75、攻击/伤害/命中/加力系数、前后摇)
- **武学**:装备位=输出武学+内功+轻功+招架;武学等级≤人物等级 且≤对应基本武学+1;提升途径=请教(潜能+经验)/练功(120 精神/h)/闭关(内功专用:完美+5/+10、普通+1/+5、走火入魔-1/-5)/研究(基本武学 500+);残页解锁主动技能(高级 5 张/顶级 10 张)
- **章节剧情**:8 卷 40+ 章,每章=MUD 式房间节点图(首章金牛武馆 17 房间),主线=逐区击败头目,房间内含拾取/翻找/送礼/决斗/切磋/请教/互动练功点(劈柴取水等:耗气血换经验)/商贩/隐藏门派入口
- **放置循环**:挂机经验与人物综合评价/传承数/福缘挂钩;12 档定时「收菜」任务(CD 1 秒~16 小时,经验 200~10000);每日任务(飞贼×50/南阳匪乱×3/送信×50/缉拿×8/古寺×1/神书/挖宝/签到);精神恢复=(下线时长/3)²
- **传承(转生)**:最多 5 转(600/700/800/900/1000 级解锁),剧情=救被掳孩童并将其四维培养至 100;得 30/40/50/50/50 先天属性点+挂机倍率;保留物品/书籍(等级清零)/4 项基本功 50 级/先天属性/福缘容貌/阅历;武学清空
- **进阶系统**(v2):经脉(八脉冲穴+真气+天赋+左右互搏)、神兵锻造、家园门客、毒药、喝茶 PVP、科举、拜访、侠义值、年龄、排行榜
- **资源**:碎银/银票/元宝(付费)/潜能/经验/精神/门派贡献/威望/阅历

## 已确认决策(用户访谈)

| 决策点 | 结论 |
| --- | --- |
| v1 范围 | A 档·精炼核心循环(见下);经脉/神兵/家园/毒药/PVP/科举 → v2 |

| 命名/路由 | 「放置武林」`/games/wulin`,目录 `src/games/wulin/`;页面副标题注明「玩法致敬《放置江湖》」 |

## v1 功能范围(A 档明细)

1. **角色创建**:4 出身(原创名:孤儿/武学世家/书香门第/商贾之家可沿用——属通用词)+属性随机/重roll;姓名输入
2. **门派**:6 正派/中立(少林·男、武当·男、峨眉·女、华山、丐帮、唐门)+1 隐藏门派(传承后解锁,原创名如「玄夜楼」);入门要求、拜师剧情、师傅 NPC 请教、3 档师门任务、贡献商店;散人路线(公共武学+基本武学自学)
3. **章节**:第一卷(原创卷名,如《风起青萍卷》)10 章,每章 5~8 房间节点;主线头目推进、支线、拾取/翻找/送礼/互动练功点/商贩;卷末 BOSS+悬念钩子(替代原作幽冥教线的原创主线)
4. **武学**:6 基本武学(拳脚/招架/内功/轻功/剑法/刀法+读书识字)+每门派 5~8 式,共约 44 式;转化率/攻防命中加力系数/前后摇/招式名/武器类型/残页主动技能;请教/练功/闭关/研究四途径与等级上限规则
5. **战斗**:完整复刻行动条机制(黄条 3.0/连击递减/前后摇/部位命中/闪避招架/加力/主动技能 CD/受伤降血上限/打坐 2 倍内力);切磋/决斗/挂机三种模式
6. **装备**:武器 6 类×3~4 品阶+部位防具(头/颈/身/手/足/腰);拾取/掉落/购买;背包容量可升级
7. **放置**:地图挂机(经验/潜能/碎银每小时,随综合评价/传承数/福缘增长);12 档收菜任务(沿用原作 CD 结构、原创任务名);每日任务 5 种(缉盗/剿匪/送信/缉拿/古寺改名原创)+签到;离线结算(挂机收益 cap:速成 8h/标准 24h;精神=(离线秒/3)²;练功/闭关延续至精神耗尽;回站弹「江湖快报」面板)
8. **传承**:最多 3 转(压缩阈值:300/500/700 级);简化传承剧情(副本救弟子→培养四维→传承);属性点 30/40/50;保留清单(物品/书籍清零/基本功 50 级/先天属性/福缘容貌/半数碎银);每转挂机倍率 +25%;可换门派
9. **设置**:静音、双档节奏切换、导出/导入存档文本、重置存档

**明确不做(v2+)**:经脉、神兵锻造、家园、毒药、喝茶 PVP、科举、拜访、侠义值、年龄增长、排行榜、第二~八卷、其余门派、面具外观、打字钩子、内购/付费(福缘仅出身+传承提供)。

## 架构设计

遵循涂鸦跳跃(自研 Pixi 游戏)既有模式,**纯 SPA 原生集成,非 iframe**:

```
apps/web/src/games/wulin/
├── constants.ts        # 平衡常量、PACE 双档倍率表、事件类型
├── types.ts            # 角色/武学/地图/装备/任务/存档 类型定义
├── sim/                # 纯 TS 模拟层(不依赖 Pixi/DOM;时钟可注入,e2e 可快进)
│   ├── character.ts    # 有效属性、面板公式(攻击/命中/闪避/防御/内力上限)
│   ├── combat.ts       # 行动条战斗模拟(可单测、可倍速、可离线无关)
│   ├── training.ts     # 请教/练功/闭关/研究(精神消耗、转化率、上限规则)
│   ├── idle.ts         # 挂机收益 + 离线结算(基于时间戳差分)
│   ├── quests.ts       # 每日任务/收菜任务 CD 与奖励
│   └── inheritance.ts  # 传承判定/保留清单/属性点分配
├── data/               # 静态内容(类型化 TS 模块,原创文案集中于此)
│   ├── origins.ts  sects.ts  skills.ts  chapters.ts  items.ts  npcs.ts
├── render/             # Pixi 渲染层
│   ├── ink.ts          # 水墨风共用绘制(剪影人物/笔触山水/墨迹粒子)
│   ├── battleScene.ts  # 战斗场景(小人对打、三槽条、飘字、招式特效)
│   └── mapScene.ts     # 章节地图(房间节点图、人物行走、交互点高亮)
├── assets/             # 少量自制 SVG/PNG(Vite import,不进 public/,无预渲染冲突)
├── audio.ts            # WebAudio 程序合成音效(刀剑/拳风/升级/翻页),可静音
└── save.ts             # localStorage `type-happy:wulin:v1`,版本化/损坏重置/导出导入

apps/web/src/components/games/WulinGame.vue   # Pixi 画布 + DOM 面板混合;底部 tab(人物/门派/地图/武学/背包/任务/传承/设置)
apps/web/src/views/WulinGameView.vue          # 路由页(返回链接+标题+说明)
apps/web/scripts/e2e-wulin.mjs                # Playwright e2e(仿 e2e-doodle.mjs)
```

**关键机制**:

- **时钟模型**:战斗用 Pixi ticker 逐帧推进(可 1x/4x 倍速观看);挂机/练功/CD/离线全部基于 `Date.now()` 时间戳差分,sim 接受注入时钟,e2e 与调试钩子可快进
- **双档节奏**:`PACE = { fast: {exp:60, train:60, cd:30, ...}, standard: {...:1} }`(实现时校准),所有速率查表;切换只影响后续增量,存档记录当前档位
- **综合评价**:武学等级+属性+传承数加权 → 挂机收益倍率 + 写入主站 games store(`recordScore('wulin', 评价, 0)`,页面卸载与传承时节流上报)
- **UI 分工**:Pixi 竖屏视口(上)展示当前地图/战斗;DOM(Tailwind,下)承载全部面板与底部 tab,视觉沿用站内风格;竖屏手机式框体(参考 DoodleJumpGame 的容器,但用 flex 纵向布局自适应高度)
- **存档**:节流持久化(同 doodle),损坏自动回退默认档;导出/导入 base64 文本

**站点集成清单**:

- `src/router/index.ts`:新增 `/games/wulin`(name `game-wulin`,TDK meta + `ld:'VideoGame'`)
- `src/views/GameListView.vue`:新增卡片(badge 🏯、gradient 如 `from-amber-400 to-rose-400`、文案含「玩法致敬《放置江湖》」)
- `scripts/seo-routes.mjs`:`gamePaths` 追加 `/games/wulin`(sitemap+prerender 自动覆盖)
- README:游戏模块表格+新小节(架构/构建/e2e 用法)
- 不新建 `public/games/wulin/`(素材走 Vite import,规避预渲染快照同名冲突)

## 实施任务(有序)

1. **骨架**:types.ts + constants.ts(含 PACE)+ save.ts;WulinGame.vue 容器(竖屏框+tab 导航占位)+ WulinGameView.vue + 路由/列表卡/seo-routes 接线;`window.__wulin` DEV 钩子
2. **角色与公式**:sim/character.ts(出身 roll、有效属性、面板公式)+ 角色创建 UI(出身选择/属性重roll/命名)
3. **数据第一批**:origins/items/skills(6 基本武学+华山全套)/chapters(前 2 章)/npcs/sects(华山)——先打通单门派垂直切片
4. **战斗**:sim/combat.ts + render/ink.ts + battleScene.ts(水墨剪影 1v1、三槽条、飘字、招式特效、切磋/决斗入口)
5. **地图探索**:render/mapScene.ts + 房间交互(移动/拾取/翻找/对话/送礼/决斗/练功点)+ 主线头目推进
6. **武学成长**:请教/练功/闭关/研究 sim/training.ts + 武学面板(装备位/系数展示/残页)
7. **放置与任务**:sim/idle.ts + sim/quests.ts + 收菜/每日任务/签到 UI + 离线结算「江湖快报」
8. **内容补全**:其余 5+1 门派、第一卷 10 章、44 式武学、80 件物品、每日任务文案(数据驱动,可分批)
9. **传承**:sim/inheritance.ts + 传承副本地图 + 弟子培养 + 转生流程 UI(3 转)
10. **打磨**:audio.ts 音效、设置页(静音/双档切换/导出导入/重置)、games store 上报、README 更新
11. **验证**:e2e-wulin.mjs + 全量检查(见下)

## 验证计划

- `pnpm typecheck && pnpm lint`(仓库根)
- dev server 手动冒烟:创建角色→拜师→清 2 章→战斗→练功→挂机→离线重进结算→传承一次
- `pnpm --filter @type-happy/web exec vite --port 5199 &` 后 `E2E_BASE=http://localhost:5199 node apps/web/scripts/e2e-wulin.mjs`:覆盖加载、角色创建、战斗胜负、练功升级、存档持久化(reload)、离线结算、传承(钩子快进)、控制台无报错
- `pnpm build && pnpm --filter @type-happy/web prerender`:确认 /games/wulin 快照生成、无 game.html 类冲突
- Docker 可选:`docker compose up -d --build` 冒烟

## 风险与对策

- **内容量是最大成本**(10 章×~7 房间×NPC 文案+44 式武学数据):数据驱动集中在 data/,按任务 3→8 分批,前 2 章+1 门派即可先上线内测
- **数值平衡**:公式借原作骨架但节奏压缩,双档倍率需实测校准;靠 `__wulin.fastForward()` 钩子在 e2e 里验证 3 转全流程可达
- **水墨剪影表现力**:首版从简(剪影+笔触+粒子),后续迭代,不阻塞上线
- **localStorage 体量**:物品/房间状态多,存档 JSON 预计 <500KB,节流写入,安全
